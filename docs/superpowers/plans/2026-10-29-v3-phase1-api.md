# Rooster v3 Phase 1 — Agent API Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Expose the existing Rooster agent as a streaming HTTP API, without changing agent behavior, so the Phase 2 web app and Phase 3 voice service can be built on it.

**Architecture:** First record a baseline of agent behavior. Then move the per-turn orchestration out of Streamlit's `render_chat()` into a UI-free `agent/turn.py` that reports progress through an `emit` callback, and switch Streamlit to it. A FastAPI service in `api/` runs turns in a worker thread, streams events as Server-Sent Events, and persists conversations in Postgres. Intel-tab queries move to a UI-free module served by read endpoints.

**Tech Stack:** Python 3.11, FastAPI, uvicorn, SQLAlchemy (existing engine), Postgres + PostGIS, pytest, httpx (FastAPI TestClient).

**Spec:** `docs/superpowers/specs/2026-10-29-v3-api-web-voice-design.md` (§5.1 and §6 Phase 1)

## Global Constraints

- No changes to planner, semantic layer, tools, synthesiser prompts or dbt models (spec §2 non-goals).
- Streamlit keeps working throughout; every task leaves `streamlit run app.py` functional.
- Config only from environment variables; new vars: `ROOSTER_API_KEY` (shared secret), `TEST_DATABASE_URL` (tests only).
- Auth header name: `X-Rooster-Key`. The API is never called from a browser, so no CORS middleware.
- New DB objects live in a new schema `app`; nothing is written to `raw`, `core` or `analytics`.
- User-facing strings stay in Spanish and come from `agent/ui_es.py`.
- Python 3.11 (matches `sandbox/Dockerfile`).
- Commits: author `miguelfa77`, no AI attribution lines (see `.claude/CLAUDE.md`).

## Review Focus

1. **A second message sent to a conversation while a turn is still running** — must not interleave state; the API answers `409` and the running turn completes normally.
2. **Client disconnects mid-stream** — the turn still finishes and is saved, so reloading the conversation shows the full answer.
3. **Execution results containing non-JSON types** (Decimal, datetime, shapely geometry) — must serialize into SSE events and into `jsonb` without crashing.
4. **The agent raises inside a turn** — the stream sends one `error` event with the Spanish fallback text, then `done`, and the conversation stays usable.
5. **Unknown conversation id or missing/wrong `X-Rooster-Key`** — `404` and `401` respectively, never a 500.
