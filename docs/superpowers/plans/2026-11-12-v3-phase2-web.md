# Rooster v3 Phase 2 — Web App Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace Streamlit with a Next.js + TypeScript web app (chat + Intel) that is a thin client of the Phase 1 API, and make the whole stack runnable locally.

**Architecture:** The browser talks only to Next.js; one catch-all route handler forwards `/api/rooster/{conversations,intel}/…` to FastAPI with the shared key and streams SSE through. The API gains published response models and one ordered `blocks` list per assistant message; the web renders those blocks with one component per primitive kind. Types are generated from `api/openapi.json`.

**Tech Stack:** Next.js ≥15 (App Router) · React 19 · TypeScript (strict) · CSS Modules · Recharts · maplibre-gl (direct, no wrapper) · react-plotly.js + plotly.js-dist-min (lazy, `code` only) · react-markdown + remark-gfm · openapi-typescript · Vitest + Testing Library (jsdom) · Playwright · FastAPI/Pydantic (existing).

**Spec:** `docs/superpowers/specs/2026-11-12-v3-phase2-web-design.md` (addendum) and its parent `docs/superpowers/specs/2026-10-29-v3-api-web-voice-design.md`.

## Global Constraints

- UI copy is Spanish; code, comments, docs, commits are English.
- Commits: no AI attribution (no `Co-Authored-By`, session links, "Generated with").
- No agent logic, SQL, or row→primitive routing in TypeScript. The browser never sees `ROOSTER_API_KEY` and never calls FastAPI directly.
- Server-only env: `ROOSTER_API_URL` (e.g. `http://localhost:8000`), `ROOSTER_API_KEY`. No `NEXT_PUBLIC_*` secrets. No host-specific APIs (no Vercel/Railway SDKs, no edge runtime); route handler uses `export const runtime = "nodejs"` and `export const dynamic = "force-dynamic"`.
- Palette (CSS variables in `web/src/app/globals.css`): `--bg #0e0e0e`, `--card #161616`, `--border #2a2a2a`, `--text #f0f0f0`, `--muted #a8a8a8`, `--accent #e03030`; transit `#534AB7`/`#1D9E75`/`#888780`; listing strokes venta `#E95D4F`, alquiler `#48A9DA`; VUT `#EF9F27`.
- Basemap: CARTO dark raster `https://{a-d}.basemaps.cartocdn.com/dark_all/{z}/{x}/{y}.png` with attribution "© OpenStreetMap contributors © CARTO". Valencia center `[-0.3763, 39.4699]`, zoom 12.
- Phone width target: 390 px with no horizontal page scroll (tables/charts may scroll inside their own container).
- Python suite (`python3 -m pytest -q`) stays green after every task.
- Make surgical changes (Karpathy guidelines); no new layers beyond what a task names.

## Review Focus

1. **SSE split across network chunks**, including a multi-byte character ("á", "€") split between chunks and an event split mid-`data:` line → parser buffers bytes and yields exactly the original events (Task 3).
2. **Stream ends without `done`, upstream non-2xx, or API unreachable** → the turn shows the fallback card with Spanish copy and the input re-enables; the proxy returns 502 JSON `{"detail":"upstream_unavailable"}` when FastAPI is down (Tasks 2, 3).
3. **Stale conversation id in localStorage** (GET 404) → silently cleared; the next send creates a new conversation (Task 3).
4. **Descriptor with `data: []`, null cells, or null `geom`/`lat`** → component shows the "Sin datos para este gráfico." empty state instead of crashing; null features/points are skipped (Tasks 4, 5).
5. **Sending while a turn streams / 409 busy** → input disabled during a turn; a 409 shows "Rooster sigue respondiendo a tu mensaje anterior." and does not add a phantom message (Task 6).

### Task 3: SSE parsing, chat state, API client

**Files:** Create `web/src/lib/sse.ts`, `web/src/lib/chat-state.ts`, `web/src/lib/client.ts`, tests `web/tests/unit/sse.test.ts`, `chat-state.test.ts`, `client.test.ts`.

**Interfaces:**
- `parseSSE(stream: ReadableStream<Uint8Array>): AsyncGenerator<TurnEvent>` — UTF-8 streaming decode; events separated by blank line; joins multi-line `data:`; ignores comments/unknown fields; JSON-parses `data`.
- `type LiveTurn = { userText: string; thoughts: string[]; text: string; primitives: PrimitivePayload[]; followUps: string[]; error: {reason: string; suggestion: string} | null; status: "streaming" | "done" }`
- `type ChatState = { conversationId: string | null; messages: Message[]; live: LiveTurn | null; notice: string | null; loading: boolean }`
- `type ChatAction = {type:"loaded"; id: string; messages: Message[]} | {type:"reset"} | {type:"send"; text: string} | {type:"event"; event: TurnEvent} | {type:"finished"; messages: Message[]} | {type:"failed"; reason: string} | {type:"busy"}`
- `chatReducer(state: ChatState, action: ChatAction): ChatState` — `finished` replaces `messages` with the server's and clears `live`; `failed` sets `live.error` with `COPY.chatErrorSuggestion` and `status:"done"`; `busy` clears `live` and sets `notice` to the 409 copy (Review Focus 5).
- `client.ts`: `createConversation(): Promise<string>`, `getConversation(id): Promise<ConversationOut | null>` (404 → null), `sendMessage(id, text, signal?): Promise<Response>` — all against `/api/rooster/...`. `STORAGE_KEY = "rooster.conversationId"`.
- `useChat()` hook in `chat-state.ts` (or `use-chat.ts`): on mount loads id from localStorage → `getConversation` → `loaded`, or clears key on null (Review Focus 3); `send(text)`: creates conversation if none (persist id), dispatches `send`, posts, 409 → `busy`, non-2xx/no body/throw → `failed`, iterates `parseSSE` dispatching `event`; after the stream ends: if no `done` was seen → `failed` (Review Focus 2), else `getConversation` → `finished`; `reset()` clears storage and state.
